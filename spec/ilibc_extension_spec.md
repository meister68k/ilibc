## 1. 目的と適用範囲

本書は、ilibcの**非標準公開拡張API**について、一覧、公開方法、共通規則、依存関係、試験との対応、将来の追加方針を定める。関数ごとの厳密な動作、境界条件、変換アルゴリズム、失敗時のバッファ内容は **ILIBC-STL-001を唯一の詳細仕様の正本**とし、本書に重複して規定しない。両文書の記述に食い違いが生じた場合は、個別動作はILIBC-STL-001、公開範囲と共通原則は本書を優先して問題として記録し、両文書の整合を回復する。

### 1.2 初版の範囲

初版は既存の**6シグネチャのみ**を公開する。新たな関数、名前空間、公開ヘッダ、グローバル変数、コンパイル設定は追加しない。C89/C++標準ライブラリの提供関数数（37関数、`std::`43シグネチャ）にも算入しない。

## 2. 共通の設計原則

1. 拡張APIは`namespace ilibc`に配置し、`std::`およびグローバル名前空間へ導入しない。
2. 追加の動的メモリ、I/O、OS機能、浮動小数点、例外、RTTI、アセンブリを要求しない。
3. 外部の可変グローバル状態を変更せず、**`errno`を読み書きしない**。失敗は出力引数または戻り値で報告する。
4. すべて`constexpr`および`noexcept`とする。`[[nodiscard]]`は既存の関数仕様に従い、機械的に全関数へ付与しない。
5. ILP32、ASCII、固定`"C"`ロケール、単一スレッドを前提とする。整数変換の範囲もこの前提に従う。
6. 呼び出し間で隠れた状態を保持しないため、各拡張APIは再入可能とする。ただし、呼び出し元が渡すバッファ・出力先の競合やアクセス可能性は呼び出し元の責任とする。
7. `ILIBC_HOST_TEST`等のビルド設定に関する契約はILIBC-HDR-001に従う。

## 3. 公開方法とインタフェース

### 3.1 公開ヘッダ

利用者は既存の **`#include <cstdlib>`** により全拡張APIを使用する。`<cstdlib>`から内部ヘッダ`<ilibc/stdlib.hpp>`が取り込まれるが、同内部ヘッダの**利用者による直接インクルードを公開契約とはしない**（ILIBC-HDR-001 §2.1）。新規の専用公開ヘッダは設けない。

互換ラッパ`<stdlib.h>`は`<cstdlib>`を取り込むが、`ilibc::`の名前をグローバル名前空間に`using`で導入しない。

### 3.2 公開シグネチャ一覧

以下の宣言はインタフェースの概要であり、関数ごとの定義はILIBC-STL-001 §2.3、§2.5を参照する。

```cpp
namespace ilibc {
    constexpr long strtol(const char *nptr, char **endptr,
                          int base, int *err) noexcept;
    constexpr unsigned long strtoul(const char *nptr, char **endptr,
                                   int base, int *err) noexcept;
    constexpr int atoi(const char *nptr, int *err) noexcept;
    constexpr long atol(const char *nptr, int *err) noexcept;

    [[nodiscard]] constexpr int _itoa_s(int value, char *buffer,
                                        std::size_t size, int radix) noexcept;
    template <std::size_t N>
    [[nodiscard]] constexpr int _itoa_s(int value, char (&buffer)[N],
                                        int radix) noexcept;
}
```

| API群 | 関数数 | シグネチャ数 | 詳細仕様 |
|---|---:|---:|---|
| エラー出力先指定の整数変換 | 4 | 4 | ILIBC-STL-001 §2.3、§3〜4 |
| 整数の文字列化`_itoa_s` | 1 | 2 | ILIBC-STL-001 §2.5、§4.5 |
| **合計** | **5** | **6** | |

「関数数」は名前の異なる関数の数を指す。`_itoa_s`の配列版は同名の関数テンプレートである。

## 4. エラー出力先指定の整数変換API

対象は`ilibc::strtol`、`ilibc::strtoul`、`ilibc::atoi`、`ilibc::atol`。

- エラー出力先として`int *err`を受け取る。範囲外では、非nullの`err`に`ERANGE`を設定する。
- 成功時および報告対象外の入力では`*err`を書き換えない。`err == nullptr`なら報告は捨てる。
- **`errno`には触れない**。既存の対応する`std::`版は`&errno`を渡してこのAPIを呼び出す薄いラッパとする。
- 本APIが報告するエラーコードは`ERANGE`のみ。数値がない場合、無効基数、末尾に余分な文字がある場合の扱いは、ILIBC-STL-001 §3.3および§4による。
- `endptr`の更新、基数の解釈、符号・空白処理、オーバーフロー時の戻り値はILIBC-STL-001に従う。

**用途:** グローバルな`errno`を共有したくない場合、割り込みハンドラ、およびエラー条件を含む定数評価。

## 5. 整数文字列化API `_itoa_s`

- `int`値を、呼び出し側から渡された領域に文字列化する。
- 基本形は`char *buffer`と`size`を明示する。配列版は配列要素数`N`を型から取得し、`size`を省略する。
- **戻り値はエラーコード**であり、0が成功、引数不正は`EINVAL`、バッファ不足は`ERANGE`。`errno`への書き込み、`err`引数は持たない。
- 3引数の配列版に任意の`char *`を渡して要素数を自動取得することはできない。
- 使用できる基数、負数の表現、文字列の終端、失敗時のバッファ内容と書込範囲などの詳細はILIBC-STL-001 §4.5を参照する。

**用途:** `<cstdio>`が使えない環境における最小限の整数→文字列変換。I/O非依存の書式化ヘッダ`<ilibc/format.hpp>`と条件付き`<cstdio>`の`%d`書式化も、この関数の上に実装される。

## 6. `constexpr`、再入可能性、エラー処理

| 観点 | err引数版4関数 | `_itoa_s` 2シグネチャ |
|---|---|---|
| `constexpr` | あり | あり |
| `noexcept` | あり | あり |
| `[[nodiscard]]` | なし | あり |
| エラーの通知 | `*err`（非null時） | `int`戻り値 |
| `errno` | 不変 | 不変 |
| 再入可能性 | あり | あり |
| 呼び出し元の管理対象 | 入力文字列、`endptr`、`err` | 出力バッファ |

`constexpr`の成立は、引数が定数評価可能であることなど、C++の定数式に関する一般条件にも従う。エラー発生時まで定数評価できることが拡張APIを利用する利点の一つである。逆に、`std::`版の整数変換で`errno`を書き込む経路は定数評価できない（ILIBC-STL-001 §3.4）。

## 7. 実装・リンク上の条件

- 拡張APIは`<cstdlib>`経由で使えるヘッダ内`constexpr inline`関数／関数テンプレートとし、独立した`.cpp`ファイルや、`ilibc.a`内の追加外部定義を必要としない。
- `ilibc.a`が定義する外部グローバルシンボルは既存の`mem*`5個という方針を維持する（ILIBC-OVR-001 §8.2、ILIBC-STR-001）。
- 入力解析では既存の文字分類処理等への依存を許す。`<cstdlib>`から`<cctype>`が間接的に取り込まれることは既存の仕様で許容されている（ILIBC-HDR-001 §2.2）。
- ARM Cortex-M0等では整数除算のコンパイラ実行時ライブラリを必要とする場合がある。依存の有無とリンク可能性の確認はILIBC-TST-001 TC-TL-09の対象とする。

## 9. 将来の拡張候補（初版の対象外）

以下は**提案・検討対象であり、公開APIではない**。名前、型、宣言、動作は未確定とする。

| 候補 | 検討目的 | 留意点 |
|---|---|---|
| 範囲・型付きメモリ操作 | 配列長・型を用いた安全性向上、`mem*`の`constexpr`代替 | `trivially_copyable`、オブジェクト表現と代入の相違、重なりの扱い |
| 再入可能なトークン分割 | 状態を内部保持する`strtok`の代替 | 解析位置と文字列の所有権・寿命を明示する |

追加する場合はILIBC-OVR-001 §1.4の採用基準を満たすことを事前に確認し、公開インタフェースと試験項目を別途決定する。

## 10. 関連文書に対する整合修正候補

本書の確定により、**ILIBC-OVR-001のD-13「初版はA（err版）のみ」は旧記述**となる。既存の§5.5、§8.5Cと整合するよう、次の趣旨に修正することを提案する。

> 初版の拡張APIはA（err引数版4関数）とC（`_itoa_s`の2シグネチャ）に限定する。型・範囲付きメモリ操作と再入可能なトークン分割は将来候補とする。

この修正は**提案のみ**であり、本書の作成では既存ファイルを変更しない。

## 12. 追加の任意拡張（ILIBC-IO-001 v0.4）

本書の既存6シグネチャ（err引数版4つと`_itoa_s`2つ）の**初版範囲は変更しない**。その後に別途追加するオプション拡張を次のように整理する。

| 公開ヘッダ | I/O依存 | 公開API |
|---|---|---|
| `<ilibc/format.hpp>` | なし | `ilibc::snprint_f`、安全な`ilibc::sprintf` |
| `<cstdio>` | あり、選択必須 | `ilibc::print_f`、`fprint_f`、`puts`、`putstr`、`fputs`、`putchar`、`fputc`、`fwrite` |

この追加機能の動作仕様はILIBC-IO-001 v0.4が正本。既存の`<cstdlib>`に配置した6シグネチャのAPI契約、`std::`とグローバル名前空間へ追加しない原則は維持する。I/Oを使わない環境でも`<ilibc/format.hpp>`は使用できる。

## 13. 追加拡張の整理（2026-10-12）

本書の初版6シグネチャ（整数変換err版と`_itoa_s`）に関する詳細の正本は維持する。

- 新規の`ilibc::clear_errno()`、`ilibc::clear_errno(int&)`はI/O非依存の`<cerrno>`拡張であり、詳細の正本は**ILIBC-ERR-001 v0.2**。
- `fgets`、配列限定`gets`、`fgetc`、`getchar`、`fread`は**条件付き`<cstdio>`**のI/O拡張であり、詳細の正本は**ILIBC-IO-001 v0.5**。
- 本書の旧「6シグネチャのみ」は**整数変換・書式化前の拡張APIに限定した初版範囲**を指すものとする。上記は別途合意した拡張である。
- 新規APIのすべてが`errno`を書き換えないわけではない。`clear_errno()`は明示的に初期化し、I/O入力関数のerr省略版はエラー時に`detail::g_errno`へ書き込む。旧共通規則「errnoを変更しない」はerr明示版の整数変換API等に限定する。
